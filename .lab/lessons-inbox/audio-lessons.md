# 音效經驗提案(DungeonZoo 打磨第 3 輪, 音效節點)

## 提案 1 — 合併到「技術」分類最後一條(本機只有 Node 可用…), 接在句尾

- `辨識` **(續)Node 也被擋掉 tar / PowerShell, mp3 / ogg 無法解碼, 不知道截哪段、各段多響** → zip 用 Node 的 `zlib.inflateRawSync` 讀中央目錄自己解(約 25 行); mp3 不解碼也能粗估音量起伏: 逐框讀側資訊裡每個 granule 的 `global_gain`(8 位元, 每 +4 約 +6 dB), 每 2 秒取平均就看得出淡入、平穩段與收尾, 拿來挑截取窗; 不同檔之間只能粗比, 實際響度仍待試玩。ogg 截短不重新編碼: 保留標頭頁 + 前 N 頁(看 granule position), 最後一頁 header type 加 EOS 旗標、檢查碼欄位清零後重算 CRC-32(多項式 0x04C11DB7, 不反轉, 初值 0), 先拿原檔第一頁驗算對得上再寫。截出來的 mp3 開頭因位元庫(bit reservoir)解不完整, 執行時丟掉開頭 0.15 秒。(DungeonZoo 打磨第 3 輪: 群眾歡呼 mp3 依增益曲線取平穩的 6.0~14.4 秒; 騷動 ogg 從 335 KB 截到 128 KB)

## 提案 2 — 放進「素材來源」分類

- `辨識` **要「稀稀落落的掌聲」循環, 免費 CC0 只有整群人密集鼓掌的錄音** → 密集掌聲壓低音量仍是一片噪音牆, 聽不出「場子才剛暖」 → 掌聲錄音的漸弱尾段多半是零星幾個人在拍: 用 5 毫秒包絡上升 > 8 dB 抓出單拍(本例 3.8 秒抓到 16 拍), 每拍剪 90 毫秒, 再用「幾個人各自固定節奏、拍一陣停一下」的方式散佈, 位置對循環長度取模, 天生首尾無縫。密度用「每秒幾拍」控制(本例 5 人約每秒 10 拍)。同一份錄音的密集段另作收場掌聲, 兩者質感一致。(DungeonZoo 打磨第 3 輪, 效果待試玩)

## 提案 3 — 放進「技術」分類

- `辨識` **觀眾聲這類循環底層, 素材是截出來的 mp3 / ogg, 本機無法離線做循環接縫** → 解碼後在瀏覽器執行時處理: 丟頭尾、把尾段 1~1.5 秒以等功率(sin / cos)交叉淡化疊進開頭, 產生新的 AudioBuffer 再用 `loop = true` 播, 接縫無爆音; 每次進同一段時從隨機位置起播, 減少「又是同一句」的感覺。換段交叉淡化用各層自己的 GainNode 排程, 跟音效的 master 共用, 靜音一次全關。(DungeonZoo 打磨第 3 輪, 瀏覽器實測待試玩)
