### 1. 併入「交付自查」的經驗「物件的狀態外觀……超出介面給的判定框 `size`」(再現: 一個函式橫跨兩個格子大小不同的區)
- 大場面動物園 explore-3 game-b 建置設計判斷再現(非老闆回饋, 不算升格證據): `drawSkillTile` 的 `size` 是 160×160(舞台格), 但規格的技能格也會打到觀眾區, 觀眾區一欄只有 160×120; 照 `size` 畫, 觀眾區的技能格會上下各溢出 20px、壓到台口與「後台」字樣 → 介面作者只照舞台格填了 `size` → 美術以 y 落在哪一區判斷, 觀眾區自動收成 144×112; style.md 寫明「以 y > 630 判斷」並請 RD 改觀眾區座標時通知美術。較好的解法是介面多給一個區域欄位(例 `area: stage | audience`), 不靠座標猜(待製作人確認)〔P2〕

### 2. 併入「無障礙」的經驗「同一關的屬性色……挑了鄰近色相」的證據(再現: 初稿憑直覺挑色, 數字驗算才抓到)
- 大場面動物園 explore-3 game-b 建置自查(非老闆回饋, 不算升格證據): 四種魔物初稿挑「火紅 / 雷黃 / 水藍 / 石紫」, 直覺覺得差很多; 用 node 算 HSV 與灰階後, 火 6° vs 雷 62° 只差 56°(且紅—黃屬相鄰色名), 水 208° vs 石 260° 只差 52°、灰階 145 vs 151 幾乎一樣 → 種類色以「每種一個典型色名」直覺挑, 沒驗算 → 定稿前一律用幾行 node 算出每色的色相與灰階貼進 style.md; 本作改成 6° / 69°(黃綠, 刻意離開黃)/ 213° / 277°、灰階 106 / 129 / 174 / 210〔P4〕

## 提案(魔物大遊行 explore-3 game-c, 美術建置)

### 1. 併入「狀態可辨識」的經驗「量條上的固定刻度與警告段寫死了規格當時的數值」(再現: 預警填色進度)
- 大場面動物園 explore-3 game-c 建置設計判斷再現(非老闆回饋, 不算升格證據; 第一個非 GhostEchoV2 的情境): 技能預警採用字典「虛線框 + 由內長大的填色, 填滿 = 即將生效」, 但介面 `drawHazard` 只傳 `t`(該 phase 經過秒數), 沒傳預警總時長; 四種技能預警時長各不同(0.4~1.0 秒)且規格寫明會隨天數縮短冷卻(預警目前不變) → 美術只能把四個預警秒數寫死在 art.js 換算進度, 規格一改預警時長, 填色就會在生效前或生效後才填滿, 不報錯 → 照原經驗處理: style.md 列出寫死的秒數與來源、請製作人把總時長(`dur`)加進 state。補一條給介面作者的判準: **介面欄位只要出現「經過時間 t」, 而美術要畫的是「還剩多少」, 就同時要總長**(待製作人確認)〔P17〕〔P2〕
