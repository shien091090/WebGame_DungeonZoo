# 美術經驗提案(WebGame_DungeonZoo polish-6 設計節點)

- 【放進「共用繪圖工具 / 改版沿用」分類, 新增一條】把一種畫法收進共用小工具(例: 鍵帽工具開始自己畫方向箭頭)之後, 逐一檢查**原本自己畫符號的呼叫端**有沒有拿掉舊的那層。DungeonZoo polish-5 的教學大鍵帽先呼叫共用鍵帽(已畫箭頭), 又沿用舊碼在同一顆上疊「Z」字, 玩家看到四顆方向鍵都像好幾顆鍵疊在一起。自查法: 對每個呼叫共用工具的函式, 確認它在呼叫之後沒有再畫同一區域的字或圖形。
- 【美術節點 polish-6 補充, 合併到上一條; 若製作人改併進「交付自查」第一條(假 ctx 自測)也可】原因補一句: 舊呼叫端的 `else` 後備分支把「不是繞圈的一律畫 Z」寫死, 當初 keys 裡還有 z / x, 後來方向鍵改由共用工具畫, 後備分支就變成對方向鍵多疊一層; 語法檢查、假 ctx 不拋錯、超框檢查都過不了這種錯(兩層都在框內)。可自動化的自查: 假 ctx 額外記錄每次 `fillText` 的畫布座標, 對有「一格一個符號」約定的元件(鍵帽、圖示格), 同一格框內出現「字 + 箭頭路徑」或兩個以上的字就報錯; 另外後備分支不要把未知值畫成某個合法符號(畫空或畫預設外觀), 以免規格改掉某個值後, 後備把舊值硬套在新東西上(不掛理念: 屬交付流程; 玩家看到的後果是 P0 辨識度)。
