## 提案(大場面動物園 explore-1 / game-c 美術建置)

### 放進「交付自查」分類(新增一條, 不掛理念)

- 物件的「倒下 / 傾倒」這類旋轉姿勢超出介面給的判定框, 假 ctx 呼叫不報錯也看不出來(大場面動物園 explore-1 game-c 建置自查, 非老闆回饋: 玩家 160×160, 倒下時整個人轉 90° 再往下平移, 實際下緣超出判定框 30 像素; 被選中的候展魔物浮起 + 稀有光暈, 上緣超出 6 像素) → 姿勢與狀態是在「站著」的版型上加旋轉、位移、光暈, 只對預設狀態目測過尺寸 → 收工前的假 ctx 改成**會追蹤變換矩陣**的版本: 攔 translate / rotate / scale / save / restore, 把 moveTo、lineTo、arc、rect、fillText 的點換算回畫布座標累計外接框, 對每個有 `size` 的函式、每個狀態組合比對「外接框 ≤ 中心 ± size/2」, 同時順便抓 save/restore 不成對; 有自己 clip 的特效(表演、網的網格線)會誤報, 逐一確認是剪裁內再放行(本作: 倒下姿勢改為旋轉後縮 0.88 並重定位, 候展光暈半徑縮小)

## 提案(大場面動物園 explore-1 / game-b 美術建置)

### 合併到上一條(game-c「旋轉姿勢超出判定框」)當第二個情境 + 補兩個誤報來源
- game-b 建置自查再現(非老闆回饋): 用同一套追蹤變換矩陣的外接框檢查, 抓到 4 種物件超框 — 逃脫魔物的危險鋸齒外圈(半徑 54, 超出 2~4px)、選中的候展魔物往上浮 4px + 四角括號(超出約 6px)、嚇跑遊客的傾斜 0.22 rad + 舉手(超出約 5px)、捕獲失敗網裂開往外飛 60px(超出 50px)。共同點是**狀態外觀(選中、受驚、失敗)在站好的版型上加位移 / 旋轉 / 外圈**, 和 game-c 同一根因 → 解法照舊; 「選中」改用不位移的通道(框 + 底色)取代浮起。
- 外接框誤報兩種, 補進該條的放行清單: (1) 地上的扁橢圓影子若用 max(rx, ry) 當半徑估, 會誤報 20~80px, 外接框要分開用 rx / ry; (2) 旋轉中的圓(瞄準圈)用「圓心 ± r 的方框再乘旋轉」會多估 √2 倍, 圓要用圓心 ± r 直接算, 不經過旋轉後的方框角。

### 放進「版面 / 遮擋」分類(新增一條)〔P1〕〔P12〕
- 介面規格寫了事件演出「畫在畫面中央」, 但這款直式版面的正中央剛好是兩排籠子之間 40px 的縫, 放哪裡都會蓋到上排籠子的怒氣條(大場面動物園 explore-1 game-b 建置設計判斷, 非老闆回饋: 「大場面」字幕在連鎖最長的那一刻出現, 那一刻也正是被帶動的魔物怒氣狂飆、玩家要決定先安撫誰的時候) → 介面作者寫「中央」時想的是「醒目、置中」, 沒拿版位表對過這個點底下是什麼 → 介面只給位置的意圖、沒傳座標時, 美術拿 spec 的版位表找出事件發生當下「沒有決策資訊」的那一帶(該作: 遊客區 y 810~1000), 保持水平置中; 在 style.md 的取捨說明寫明偏離介面字面的原因和代價, 讓製作人驗收(待老闆試玩確認)
