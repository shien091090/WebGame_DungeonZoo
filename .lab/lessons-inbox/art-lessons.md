# 美術經驗提案(收件匣)

## 提案 1 — 併入「交付自查」既有經驗「說明頁以外的全畫面……介面沒寫歸誰畫」(不掛理念: 屬分工)

建議在該條尾端追加一段「反向再現」:

- 大場面動物園 deepen-2 game-a 建置設計判斷再現(非老闆回饋, 不算升格證據; 反方向的衝突): 任務單寫「說明頁的頁標題、說明文字、頁碼、翻頁提示由 RD 畫, 美術只畫示意圖」, 同一輪的 interface.json(不可更改、RD 照它寫)notes 卻寫「畫面上所有文字都由美術畫, RD 不另外畫字……drawGuidePage 畫說明頁全部文字」, 而且 state 只有一個框 `{page, x, y, w, h}`、沒分出示意圖區 → 任務單是跨輪的固定範本, interface 是這一輪製作人新加的「文字歸屬」, 兩份沒有對齊; 美術與 RD 同時開工、各讀各的, 照任務單會變成兩邊都不畫字(說明頁只剩圖), 照 interface 則在 RD 也讀了任務範本時會重疊 → 兩份衝突時照 RD 實際照著寫的那份(interface.json), 因為「兩邊都不畫」比「重疊」更糟、而且 interface 是本輪較新的明文; 在 style.md 說明頁一節開頭寫明偏離與「RD 請不要在說明頁另畫任何文字」, 回報裡請製作人二擇一統一(建議: interface 有「文字歸屬」時, 任務範本的說明頁分工段落改成「依 interface 的文字歸屬」)(待製作人確認)

  - 補充(deepen-2 game-c 美術): 同一個衝突, game-c 美術選了**任務單**那一邊(說明頁只畫示意圖 + 物件旁短標籤), 理由是任務單對美術是直接指令、而且 RD 的任務範本很可能有同一段分工; 兩款同輪做了相反選擇, 本身就證明這個衝突不能留給節點自己判斷 — 請製作人在這輪接合檢查時, 依 game-a / game-c 各自的 RD 實際行為確認說明頁沒有「沒字」或「重疊」

## 提案 game-c-1 — 放進「狀態可辨識」〔P2〕〔P1〕(大場面動物園 deepen-2 game-c 建置設計判斷, 非老闆回饋)

- 規劃階段要擺的物件(機關), 作用範圍是擺放決策的依據, 介面卻只給本體的 `size`、沒有任何函式能在布置時畫範圍(該作: 安全閥半徑 180、戰鼓 / 噴泉 160、肉塊 260, `drawGadget` 的 size 只有 80×80; 範圍只在開演後的脈衝特效裡出現, 布置時玩家看不到「這顆保險罩得到哪幾格」) → 介面作者照「物件本體多大」填 size, 沒問「玩家做決定時要看到什麼」; 美術又被「畫面邊界 = size」約束, 不能自己把範圍畫進本體函式 → 開工對介面時, 逐一問每個「放置型」物件: 擺放決策靠哪個看不見的量(範圍、方向、射程)? 介面沒有對應函式就在回報裡明講, 請製作人加一個只在布置游標停留時呼叫的範圍函式(例 `drawXxxRange`); 當版本體函式不偷畫範圍(會壓到鄰格、與 size 不符)(待製作人確認)

## 提案 game-c-2 — 放進「說明頁」, 併在「說明頁示意圖畫出規則上不成立的盤面」之後〔P3〕(大場面動物園 deepen-2 game-c 建置設計判斷, 非老闆回饋)

- 介面寫計數器「到上限就換狀態、不再顯示」(該作: 失控標記 0~4, 到 5 就失控、marks 不再顯示 5), guide 卻要求說明頁畫「頭上 5 個標記、撞破圍欄撲向觀眾」; 同頁還要求「標記 0 個、怒氣在紅區頂端」與「撞欄途中圍欄已破」, 兩者規則上都不成立(怒氣到 100 立刻出 1 個標記; 撞欄 1.5 秒後圍欄才破) → guide 作者描述的是「意思」, 沒對規則的狀態轉換時點 → (1) 計數的終點狀態由「換了的那個狀態」自己畫(該作: mode = charge / loose 時美術畫 5 格全亮, 不讀 marks), 讓說明頁與場上同一個長相; (2) guide 字面的狀態組合先拿規則逐項驗(怒氣 / 標記 / 模式 / 圍欄), 不成立就改用意思相同、規則成立的那一刻(0 標記改怒氣 90; 撞欄改成已在觀眾席亂竄), 在 style.md 寫明(待製作人驗收)

## 提案 2 — 補強提案 1 的證據(同輪第二款)

- 大場面動物園 deepen-2 game-b 建置設計判斷再現(非老闆回饋, 不算升格證據): 同一個衝突, 獨立開工的 game-b 美術也判斷照 interface 畫說明頁全部文字(標題、內文、頁碼、「按 Z 繼續 / 開始」), 並在 style.md 建議 RD 傳整個畫布當框。兩款獨立得出同一判斷 → 提案 1 的「照 interface」可直接寫進經驗的解法, 不必等製作人逐款確認; 任務範本仍需修。

## 提案 3 — 併入「無障礙」既有經驗「同一關的屬性色……鄰近色相」中「會與屬性色同框長在同一個物件上的專屬色」那段(〔P4〕〔P9〕)

- 大場面動物園 deepen-2 game-b 建置設計判斷再現(非老闆回饋, 不算升格證據; 第一個非捕泡手的情境): 六種魔物已用掉紅橘 / 黃 / 綠 / 藍 / 紫 / 灰, 規格又要「被點燃(升怒)/ 被澆熄(降怒)」兩種回饋長在**每一種**魔物身上 → 種類多到色輪排滿時, 任何專屬色都必定和某一種的本體色同名(該作: 琥珀升怒 39° vs 雷鳥 46°、青降怒 195° vs 水母 216°), 「換一個不撞的顏色」不存在 → 先承認顏色這條通道在最差組合上會失效, 把主通道交給方向(火舌往上 / 水滴往下)與形狀, 顏色降為第三通道; 回饋環一律帶深色襯環, 讓它與本體之間有明度分界; 在 style.md 色票表下寫明最差組合(被點燃的雷鳥、被澆熄的水母)讓製作人用那一幀驗收(待老闆試玩確認)
