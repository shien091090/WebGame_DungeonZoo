# 美術經驗提案(收件匣)

## 提案 1 — 放進「經驗 / 說明頁」, 新增一條
- guide.md 的「圖要示意」要求在圖下方畫一列鍵帽對照(「方向鍵 / Z / X」對應「走 / 揮鞭 / 翻滾」), 但製作人分工規定按鍵說明由 RD 畫、美術只畫示意圖(大場面動物園 explore-4 game-a 建置設計判斷, 非老闆回饋) → guide 作者把「圖要示意」寫成整頁畫面的全貌, 沒區分圖與頁面文字; 那一列對照和該頁「文字」(方向鍵走, Z 揮鞭, X 翻滾)是同一句, 照字面畫就是兩邊重複(同 GhostEchoV2 圖文重疊的根因) → 圖裡的按鍵只用鍵帽**貼在做那個動作的物件旁**(Z 在鞭旁、X 在翻滾中的角色上方、方向鍵在角色旁), 不排成獨立一列、不配動作名稱; 鍵帽本身算「物件旁的短標籤」。在 style.md 說明頁一節寫明偏離 guide 字面的原因, 讓製作人驗收(待製作人確認)〔P7〕〔P19〕〔P3〕

## 提案 2 — 合併到「經驗 / 狀態可辨識」的「量條上的固定刻度與警告段寫死了規格當時的數值」, 加一筆再現證據
- 大場面動物園 explore-4 game-a 建置設計判斷再現(非老闆回饋, 不算升格證據): 技能預警(火圈 0.5 秒、落雷 0.8 秒)採字典的「虛線外緣 + 由中心長大的填色, 長滿 = 生效」, 介面又只傳 `t`(該階段經過秒數)、沒傳預警總長; 美術照本條把總長寫進 style.md「時長常數」一節並標來源。同一個介面缺口在連續兩輪探索(explore-3 game-c、explore-4 game-a)出現, 建議製作人在出介面的流程裡加一條檢查: 任何「預警 / 倒數 / 冷卻」類 state 有 `t` 就要同時有總長欄位(例 `dur`)

## 提案 3 — 合併到提案 2(同一條「量條上的固定刻度與警告段寫死了規格當時的數值」), 再加一筆再現
- 大場面動物園 explore-4 game-b 建置設計判斷再現(非老闆回饋, 不算升格證據): 同一個缺口第三次出現, 且這次技能**同時用在兩個場景**(地下城預警 0.5 / 0.8 秒; 表演場同一個函式畫, 規格沒寫表演場預警多長) — 寫死的總長只對其中一個場景成立, 另一個場景填色一定提早或晚滿。美術照規格的地下城數值寫死、在 style.md 標出, 並請製作人加 `warnDur`。給介面的判準補一句: **同一個函式會畫在兩個以上場景、而時長只在其中一個場景有規格數字時, 更要把總長放進 state**

## 提案 4 — 放進「經驗 / 交付自查」, 新增一條(不掛理念: 屬分工)
- 非說明頁的全畫面函式(標題卡、結算面板)與 HUD 底部的操作提示, 介面沒寫「提示字由誰畫」, 美術與 RD 同時開工時兩邊都可能畫一份「按空白鍵開始 / 重來 / ←→ 選擇」(大場面動物園 explore-4 game-b 建置設計判斷, 非老闆回饋; 與說明頁圖文重疊同一根因: 分工規則只寫了說明頁, 其他畫面沒寫) → 介面的 state 沒有提示字欄位, 美術就會在函式裡自己畫; RD 照 spec 的「畫面底部提示」條文也會自己畫 → 美術在 style.md 物件表裡**逐一寫明哪些提示字已由美術畫、RD 不要再畫**(該作: 標題卡「[空白] 開始」、結算「[空白] 重來」、排位 / 表演 / 商店的底部操作列都歸美術的 HUD / 面板函式); 建議製作人在介面 notes 加一欄「畫面文字歸屬」, 把每個畫面上的提示字指定給美術或 RD 其中一方(待製作人確認)

## 提案 5 — 合併到提案 2 / 3(「量條上的固定刻度與警告段寫死了規格當時的數值」), 再加一筆再現
- 大場面動物園 explore-4 game-c 建置設計判斷再現(非老闆回饋, 不算升格證據): 同一個缺口第四次出現(火圈 0.5 / 落雷 0.8 秒, 介面只傳 `t`); 這次再擴大到**所有一次性特效**: 圍圈閃光、繩子被切、吠叫範圍、飄字也都只傳 `t`, 淡出總長全由美術自訂寫死, RD 不知道何時可以停止呼叫、要保留特效多久。美術在 style.md 列「時長常數」表(效果 / 總長 / 來源 = spec 或美術自訂), 並讓函式在 t ≥ 總長時自己不畫。給介面的判準再補一句: **一次性特效只傳 `t` 時, 總長屬美術, 但必須寫進 style.md 讓 RD 知道何時移除**

## 提案 6 — 合併到「經驗 / 說明頁」的「說明頁示意圖畫出規則上不成立的盤面」, 加一筆再現證據
- 大場面動物園 explore-4 game-c 建置自查(非老闆回饋, 不算升格證據; 第一個連續幾何規則的情境): 第 1 頁要「繩子頭尾交叉」, 第一版讓繩子從外面徑向拉進來、再繞一整圈, 看起來是一個閉合圈, 用 node 算線段相交卻是 **0 處** — 尾段在進場點的另一側往外走, 只相切不相交; 規則上這圈根本不成立(圍圈判定要「最新一段與較舊的繩段相交」) → 憑直覺畫「繞一圈」, 沒拿判定條件驗; 格子類規則還能逐格看, 連續幾何(相交、面積、距離)肉眼幾乎驗不出 → 示意圖裡任何依幾何判定的狀態(相交、圈住、在範圍內 / 外), 用 node 拿規格的判定式跑一次示意座標(該作: 讓進場方向偏離圈的起點 0.6 弧度, 尾段向外螺旋, 驗出 1 處相交), 驗算結果寫進 style.md 說明頁一節〔P3〕
